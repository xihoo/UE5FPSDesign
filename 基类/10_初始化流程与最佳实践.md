# 基类设计 · 初始化流程与最佳实践

## 初始化流程

服务器端：
1. GameInstance::Init()
2. GameMode::InitGame()
3. GameState 创建
4. PlayerController 登录
5. PlayerState 创建
6. Character 生成
7. Character::PossessedBy() → ASC InitAbilityActorInfo + 默认 Ability/Effect
8. 准备关卡逻辑（地牢生成、波次调度）

客户端：
1. GameInstance::Init()
2. 接收 GameState 复制
3. PlayerController 创建
4. PlayerState 复制
5. Character 复制
6. Character::OnRep_PlayerState() → ASC InitAbilityActorInfo（客户端）
7. 输入映射与 UI 初始化

## 最佳实践

GAS 集成：
- 在服务器与拥有客户端都调用 `InitAbilityActorInfo`。
- AttributeSet 在构造时创建；不要延迟到 BeginPlay。
- 使用 GameplayTags 做能力过滤与状态 gating。
- 伤害计算统一走 ExecutionCalculation，保持可维护性。

网络同步：
- 关键逻辑（伤害、状态改变）只在服务器执行。
- 使用 RPC 进行客户端请求（例如交互、技能激活），避免客户端直接修改。
- RepNotify 中保持轻量，不做重型搜索或 Spawn。
- 对热点变量（如移动相关）避免重复冗余复制。

组件使用：
- 单一职责：库存、技能、武器、交互分离。
- 使用接口 / 事件分发替代直接强耦合引用。
- DataAsset 注入配置（武器、角色、AI 行为参数）。
- 避免组件间双向依赖；若需要回调使用委托或弱引用。

## 扩展指南

新角色类型：
1. 继承 AFPSCharacterBase。
2. 添加专属组件（如 CloakComponent）。
3. 覆写默认能力授予逻辑（添加新 Ability）。
4. 创建角色 DataAsset（初始属性、外观、默认装备）。
5. GameMode 注册 spawn 规则。

新属性：
1. 在 AttributeSet 中添加字段与访问宏。
2. 添加 Pre/Post 回调（限制范围、触发事件）。
3. 创建 GE 修改该属性（持续 Buff、装备加成）。
4. UI 监听属性变化（ASC Delegate）。

自定义游戏模式：
1. 继承 AFPSGameMode。
2. 覆写波次/胜负判定。
3. 调整复活/资源发放逻辑。
4. DataAsset 驱动参数（波次时长、敌人分布表）。
5. 设置为地图 Override 或项目默认。

## 进一步改进建议

- 事件广播规范：统一使用 `GameplayEvent` (FGameplayTag) + Payload 结构。
- 组件生命周期钩子：定义 `OnGamePhaseChanged` 接口，组件可订阅 GameState Phase。
- 数据验证：启动时对所有 DataAsset 做一次一致性校验（缺失标签、无效类）。
- 性能审计：定期统计 Ability 激活频率与 Execution 开销。
