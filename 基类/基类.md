# 基类设计文档

## 概述

本文档定义了UE5 FPS多人PVE游戏项目的核心类层次结构。所有基类都采用C++实现，并深度集成Gameplay Ability System (GAS)，为游戏的各个系统提供统一的基础架构。

## 设计原则

1. **GAS优先集成** - 所有角色和游戏逻辑基类都集成AbilitySystemComponent
2. **网络复制支持** - 所有基类从设计之初就考虑多人游戏的网络同步需求
3. **组件化架构** - 使用组件模式分离关注点，提高代码复用性
4. **数据驱动配置** - 通过DataAsset和配置文件驱动游戏行为
5. **扩展性设计** - 预留扩展点，便于子类定制行为

## 核心类层次结构

```
UObject
├── UGameInstance (游戏实例)
│   └── UFPSGameInstance
├── AGameModeBase
│   └── AFPSGameMode (游戏模式)
├── AGameStateBase
│   └── AFPSGameState (游戏状态)
├── APlayerController
│   └── AFPSPlayerController (玩家控制器)
├── APlayerState
│   └── AFPSPlayerState (玩家状态)
├── APawn
│   └── ACharacter
│       └── AFPSCharacterBase (角色基类)
│           ├── AFPSPlayerCharacter (玩家角色)
│           └── AFPSAICharacter (AI角色)
└── AAIController
    └── AFPSAIController (AI控制器)
```

## 网络复制策略

### 角色复制
- **Position/Rotation**: 使用CharacterMovement组件的内置复制
- **Health/Shield**: 通过GAS的AttributeSet自动复制
- **Weapon State**: 自定义复制，使用ReplicatedUsing
- **Abilities**: 通过GAS的GameplayAbility复制机制

### 游戏状态复制
- **GamePhase**: ReplicatedUsing，带RepNotify
- **Wave Info**: 标准复制
- **Stats**: 标准复制

### 优化策略
- 使用条件复制减少带宽
- 对不重要的属性降低复制频率
- 实现客户端预测减少延迟感知

### 服务器端

2. GameMode::InitGame()

5. PlayerState创建

## 最佳实践

### GAS集成
1. **永远在服务器和拥有客户端上初始化ASC**
2. **AttributeSet应该在角色构造时创建**
3. **使用GameplayTags进行能力标记和过滤**
4. **伤害计算使用GameplayEffectExecutionCalculation**

### 网络同步
1. **关键游戏逻辑在服务器执行**
2. **使用RPC进行客户端到服务器的通信**
3. **重要状态变化使用RepNotify通知**
4. **实现客户端预测提升响应性**

### 组件使用
1. **保持组件职责单一**
2. **通过接口而非直接引用通信**
3. **配置数据通过DataAsset注入**
4. **避免组件间的循环依赖**

## 扩展指南

### 添加新角色类型
1. 继承AFPSCharacterBase
2. 添加特有组件
3. 覆写必要的虚函数
4. 创建对应的DataAsset配置
5. 在GameMode中注册

### 添加新属性
1. 在AttributeSet中添加属性
2. 实现属性的Getter
3. 添加Pre/PostAttributeChange回调
4. 创建对应的GameplayEffect
5. 更新UI显示

### 自定义游戏模式
1. 继承AFPSGameMode
2. 覆写游戏流程相关函数
3. 添加自定义规则逻辑
4. 配置GameMode DataAsset
5. 在Project Settings中设置为默认
